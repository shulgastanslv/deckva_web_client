# Система подписок

## Зачем так

Раньше Pro висел на **организации** (`Organization.isUpgrade`): любой участник workspace получал лимиты «через» орг, а оплату по сути не было — флаг просто переключали.

Сейчас подписка **личная**. Это проще для BYN-биллинга (карта привязана к человеку), прозрачнее для отмены и истории платежей и ближе к модели «один аккаунт — один Pro», как у большинства SaaS. Командная работа остаётся через организации, но **право на Pro-фичи** смотрит на подписку пользователя (для инвайтов — на Pro владельца орг).

Цена: **15 BYN в месяц**. Без триала.

## Что хранится

| Сущность | Назначение |
|----------|------------|
| `User.subscriptionStatus` | `NONE` / `ACTIVE` / `PAST_DUE` / `CANCELED` |
| `User.subscriptionEndsAt` | конец оплаченного периода |
| `User.cancelAtPeriodEnd` | отмена в конце периода, доступ до даты |
| `PaymentMethod` | токен карты + brand / last4 / срок (PAN и CVV не храним) |
| `BillingPayment` | история списаний и отказов |

Ключевые файлы: `lib/studio/plans.ts`, `lib/billing/*`, `actions/billing.ts`, UI в `studio-upgrade-dialog.tsx` и секции Billing в `profile-settings-dialog.tsx`.

## Как проходит оплата

```
Карта → tokenize → PaymentMethod
       → subscribePro → списание 15 BYN
       → ACTIVE + subscriptionEndsAt (+1 месяц)
```

1. **Привязка карты** — валидация номера (Luhn), токенизация, запись метода оплаты.
2. **Подписка** — списание первого месяца, статус `ACTIVE`.
3. **Отмена** — `cancelAtPeriodEnd = true`, Pro работает до `subscriptionEndsAt`.
4. **Возобновление** — сброс флага отмены.
5. **Продление** — при проверке `userHasPro`: если период кончился и отмены нет, снова списываем карту. Отдельного cron/webhook пока нет.

### Провайдер

- Есть `BEPAID_SHOP_ID` + `BEPAID_SECRET_KEY` → **bePaid** (Беларусь, BYN).
- Иначе → **sandbox**: токены `sandbox_*`, списания всегда успешны (для разработки).

Env описаны в `.env.example`.

## Что даёт Pro

| Free | Pro |
|------|-----|
| до 3 каруселей на пользователя | без лимита |
| без папок | папки |
| инвайты только если у владельца орг есть Pro | то же правило для принятия в команду |

Маркетинговые пункты вроде «brand kits» и «hi-res export» в UI есть; отдельной сущности brand kits в схеме пока нет.

## Почему не org-billing и не seats

- Локальный рынок и bePaid ориентированы на оплату физлица / ИП.
- Цена фиксированная **15 BYN**, без тарифов по местам — меньше сложности на старте.
- Организация остаётся контейнером проектов и ролей, а не биллинговой единицей.

## Ограничения текущей реализации

- Продление «ленивое» (в момент проверки Pro), не по расписанию.
- Нет вебхуков bePaid и PDF-чеков.
- Без ключей bePaid всё крутится в sandbox — для продакшена ключи обязательны.
